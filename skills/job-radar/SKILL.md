# job-radar: 채용 공고 수집

`job-radar` MCP 서버(search_jobs, get_job_detail, fetch_jobs, list_companies)와 노션 MCP를 쓴다.

## 0. 연결 확인

- 노션 도구(예: `notion-search`, `notion-create-pages`)를 쓸 수 있는지 본다. 없으면 아래를 안내하고 끝낸다.
  - claude.ai 설정 → 커넥터에서 Notion 연결 (Claude Code에 같은 계정으로 로그인돼 있으면 자동으로 보임), 또는
  - `claude mcp add --transport http notion https://mcp.notion.com/mcp` 후 `/mcp`에서 로그인
- `job-radar` 도구(`search_jobs`)가 없으면 README의 설치 명령(`claude mcp add job-radar ...`)을 안내하고 끝낸다.

## 1. 사용자 설정

`~/.job-radar/profile.yaml`을 읽는다. 있으면 2단계로. 사용자가 "설정 바꿔줘"라고 했거나 파일이 없으면 아래 순서로 만든다.
자동 실행(예약 실행)이라 물어볼 수 없으면 "설정 파일이 없다"고 보고하고 끝낸다.

**질문** (한 번에 묻는다, AskUserQuestion이 있으면 사용):
1. 원하는 직무 (자유롭게. 예: "백엔드 개발, 서버", "AI 엔지니어, 데이터 분석")
2. 연차: 신입이면 0, 경력이면 몇 년. 이 값까지 요구하는 공고를 넣는다
3. 기업 분류 (여러 개): 대기업, 대기업 계열사, 중견기업, 강소·유망, 공기업, 외국계
4. 빼고 싶은 공고 (없어도 됨. 예: 계약직, 지방 근무, 교육 직무)

**키워드 만들기**: 직무 답을 보고 Claude가 만든다. 사용자에게 키워드를 묻지 않는다.
- `keywords`: 공고 제목에 나올 말을 한글·영어로 (예: 백엔드 → [백엔드, Backend, 서버, Server, Java, Spring, Node]). 짧은 영어 단어는 단어 단위로 맞춰지므로 그대로 써도 된다.
- `exclude_keywords`: 연차보다 높은 직급(예: 신입·주니어면 [Staff, Principal, Lead, 리드, 시니어, Senior]) + 4번 답 중 제목에 나올 말(예: 강사, 계약직). 제목만으로 못 거르는 조건(예: 지방 근무)은 `avoid`에 두고 4단계에서 판단한다.
- 만든 키워드를 보여 주고 고칠 게 있는지 한 번 확인한다.

**노션 DB 고르기**: 이미 쓰는 공고 DB가 있는지 묻는다.
- 있으면: 이름이나 링크를 받아 fetch로 찾고 data source ID를 적는다. 그 DB의 열 이름과 선택지를 따른다.
- 없으면: 어느 페이지 아래에 만들지 묻고(없으면 개인 페이지 최상단) 「채용 공고 DB」를 만든다. 열:
  - 회사 / 공고 (제목), 기업 분류 (선택: 대기업, 대기업 계열사, 중견기업, 강소·유망, 공기업, 외국계)
  - 직무 (다중 선택: 사용자의 직무 답을 3~6개로 나눈 값), 세부 직무 (텍스트)
  - 경력 (선택: 신입, 신입~1년, 신입~2년, 신입~3년, 경력무관, 경력 1년↑, 경력 2년↑, 경력 3년↑, 경력 5년↑, 경력(연차 미기재))
  - 마감일 (날짜), 근무지 (텍스트), 공식 지원 링크 (URL), 채용 유형 (선택: 취업연계형, 정규직, 계약직, 인턴), 메모 (텍스트)

**저장**: `~/.job-radar/profile.yaml`

```yaml
roles: "백엔드 개발, 서버"          # 직무 답 그대로
keywords: [백엔드, Backend, 서버, Server]
exclude_keywords: [Staff, Principal, Lead, 시니어]
max_career: 1                       # 연차 답
avoid: "계약직, 지방 근무"           # 4번 답 그대로 (없으면 "")
categories: [대기업, 대기업 계열사, 중견기업]
notion_data_source: "<data source ID>"
```

저장한 뒤 바로 2단계부터 첫 수집을 한다.

## 2. 마감 공고 정리

DB에서 마감일이 오늘 이전인 공고를 찾아 삭제한다. 마감일이 없는 공고(상시)는 그대로 둔다.

## 3. 공고 수집

`search_jobs(keywords, max_career, categories, exclude_keywords)`를 profile 값으로 호출한다.

결과의 `manual_check`(그룹 채용 사이트 등)는 각 url을 WebFetch로 읽어 같은 기준으로 공고를 찾는다. 페이지를 읽을 수 없으면 건너뛰고 보고에 적는다.

## 4. 거르기 (Claude 판단)

`search_jobs`는 제목만 보고 1차로 거른 것이다. 각 공고를 다음 기준으로 다시 본다.
- `roles`에 맞는 직무인가. 제목에 "데이터"가 있어도 검수·운영 스태프, 데이터 라벨링 아르바이트 등은 제외.
- 경력: `career_min`이 None(모름)이거나 「경력」처럼 연차가 없으면 `get_job_detail(url)`로 본문을 읽어 자격 요건의 연차를 확인한다. `supported=False`일 때만 WebFetch로 연다. `max_career`보다 많이 요구하면 제외 (우대 사항이 아니라 자격·지원 조건 기준).
- 헤드헌팅, SI 파견 공고는 제외. profile의 `avoid`(빼고 싶은 공고)에 해당하면 제외.
- 「상시 인재풀」「인재 등록」처럼 특정 포지션이 없는 공고는 제외.
- 마감일이 없으면 본문에서 확인하고, 그래도 없으면 비워 둔다(상시).

## 5. 노션에 넣기

- 중복 확인: DB의 「공식 지원 링크」와 같은 url이 이미 있으면 넣지 않는다. 제목과 회사가 같은 공고도 넣지 않는다.
- 회사 / 공고: `회사명 공고제목` 형식.
- 기업 분류: 결과의 `category`.
- 경력: 확인한 연차를 선택지에 맞춘다. 선택지에 없는 값(예: 1년 이상)은 「경력(연차 미기재)」로 두고 메모에 적는다.
- 전환형 인턴·채용 연계 대회는 채용 유형을 「취업연계형」으로.
- 메모에는 판단 근거를 짧게 (예: "자격 요건 2년 이상", "신입/경력 모두 지원 가능").

## 6. 보고

마지막에 짧게 보고한다: 새로 넣은 공고 수와 목록(회사·제목), 지운 마감 공고 수, 수집 실패한 회사(`errors`), 읽지 못한 채용 페이지.
